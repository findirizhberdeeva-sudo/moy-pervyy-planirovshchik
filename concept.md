# Концепция проекта «Ритм»

Дата: 1 ноября 2026 года.

«Ритм» — простой командный планировщик рабочих задач. Он помогает организовать месяц по неделям, сосредоточиться на текущем дне и быстро оценить результаты команды и каждого сотрудника.

Документ описывает будущий продукт. Код, файлы страницы, облачный проект и публикация на этом этапе не создаются.

## 1. Согласованные требования

- Одна общая доска для руководителя и сотрудников с одинаковыми актуальными данными на компьютере и телефоне.
- Сотрудники создают задачи себе; руководитель может назначать задачи сотрудникам.
- Фильтрация по исполнителю, статусу, приоритету и срокам.
- Планирование месяца по неделям. Неделя всегда содержит семь дней с понедельника по воскресенье; основные рабочие дни — понедельник–пятница.
- Текущий день занимает главное место, неделя представлена компактнее, месяц доступен для общего обзора.
- Быстрое добавление неожиданных задач, редактирование, удаление и перенос на другие даты и недели.
- Пять статусов: «В плане», «В работе», «Ожидает ответа», «Выполнено», «Отменено».
- Четыре сочетания важности и срочности.
- Длительные и регулярные задачи.
- Автоматический перенос незавершённых задач на следующий день.
- Общий и индивидуальный прогресс за день, неделю и месяц; учёт часов не требуется.
- Начало работы с пустой доски. Импорт из Google-таблиц и ручной обмен файлами между устройствами не нужны.
- Интерфейс на русском языке, спокойный современный дизайн.
- Три файла интерфейса: `index.html`, `styles.css`, `app.js`. Размещение страницы на GitHub Pages.

**Уточнение первоначального ограничения хранения:** пользователь согласовал облачное хранение для общей доски. Рабочие данные будут общими; localStorage останется для настроек конкретного браузера. Требование хранить все задачи исключительно в localStorage заменено этим решением.

Далее приведены предлагаемые решения по интерфейсу, правилам расчётов и техническому устройству.

## 2. Основная идея интерфейса

После входа пользователь сразу видит сегодняшний день, ближайшие задачи недели и короткий итог месяца. Для повседневной работы не нужно каждый раз открывать календарь и заполнять подробную форму.

Основная навигация: «План» и «Итоги». На экране «План» день, неделя и компактный обзор месяца доступны одновременно. Отдельное раскрытие месяца помогает спланировать более дальние даты.

На компьютере экран состоит из следующих областей:

| Область | Содержание |
| --- | --- |
| Верхняя панель | Название, выбранный месяц, переходы назад/вперёд, кнопка «Сегодня», выбор сотрудника, «Добавить задачу» |
| Краткий прогресс | Выполнение плана дня, недели и месяца: процент и подпись «6 из 10» |
| «Сегодня» — главный блок | Крупные карточки задач, быстрый ввод, сроки, статусы и быстрые действия |
| «Неделя» — соседний блок | Семь компактных дней с задачами и возможностью переноса |
| Обзор месяца | Пять или шесть недель календаря, количество задач и индикаторы нагрузки по дням |

Блок дня занимает примерно 55–60% основной рабочей области. При выборе другой даты он показывает её задачи; кнопка «Сегодня» возвращает текущий день. Просмотр прошлой или будущей недели сам по себе не изменяет задачи.

В месячном обзоре видны границы недель и соседние даты предыдущего и следующего месяца. Нажатие на неделю открывает её в недельном блоке, на дату — соответствующий день.

## 3. Визуальный стиль

Рабочее название — «Ритм». Визуальное направление: светлая рабочая панель с чёткой типографикой, свободным пространством и небольшими цветными метками.

| Элемент | Предложение |
| --- | --- |
| Фон | Светло-серый `#F5F6F8` |
| Карточки | Белый `#FFFFFF`, тонкая граница, мягкое скругление |
| Основной текст | Графитовый `#24303F` |
| Основной акцент | Приглушённый синий `#55657E` |
| Выполнение | Спокойный зелёный `#3F6655` |
| Приближение срока | Приглушённый янтарный `#8A6245` |
| Просрочка | Сдержанный красный `#9B4B50` |

Шрифт — системный, без обязательной загрузки внешних шрифтов. Цвет дополняет текстовые подписи и значки. Контраст текста и кнопок проверяется при реализации, особенно на небольших метках.

Вместо звёзд, рейтингов сотрудников и анимации наград используются небольшие шкалы прогресса и спокойные сообщения: «Сегодня выполнено 4 из 6 задач», «План дня завершён». Пустой день сопровождается предложением добавить задачу. Соревнование между сотрудниками не вводится.

## 4. Создание и карточка задачи

Быстрый ввод находится прямо в блоке дня и доступен через кнопку «Добавить задачу».

| Поле | Поведение |
| --- | --- |
| Название | Обязательно; можно сохранить задачу нажатием Enter |
| Плановая дата | Подставляется выбранный день, по умолчанию сегодня |
| Исполнитель | При фильтре конкретного сотрудника подставляется он; в режиме всей команды — текущий пользователь. Сотрудник назначает только себе |
| Приоритет | Выбирается из четырёх сочетаний; можно заполнить позже |
| Срок сдачи | Необязательная отдельная дата |
| Описание | Необязательный текст |
| Конец периода работы | Дополнительное поле для длительной задачи |
| Повторение | Дополнительная настройка регулярной задачи |

Для быстрого сохранения достаточно названия: плановая дата и исполнитель уже заполнены. Новый статус — «В плане». Пока приоритет не выбран, показывается нейтральная подпись «Приоритет не задан»; задача не получает оценку важности автоматически.

Точное время, отдельное поле ссылок, участники встречи, повестка и учёт трудозатрат в первую версию не включаются. При необходимости ссылку можно вставить в описание.

Компактная карточка показывает название, исполнителя, статус, приоритет и срок, если он задан. Описание раскрывается по нажатию. Доступные действия: завершить, изменить статус, перенести, открыть подробности, убрать задачу. Завершение можно отменить.

Завершённые задачи остаются в сворачиваемой группе своего дня. Отмена задачи означает, что работа больше не требуется. Удаление убирает ошибочно созданную карточку с доски с возможностью отменить действие; история сохраняется для корректных итогов.

## 5. Статусы, важность и сроки

| Статус | Значение |
| --- | --- |
| В плане | Задача запланирована, работа ещё не начата |
| В работе | Исполнитель работает над задачей |
| Ожидает ответа | Для продолжения требуется ответ или внешнее действие |
| Выполнено | Задача завершена; сохраняется фактическая дата завершения |
| Отменено | Задача больше не требуется; учитывается отдельно |

Приоритет состоит из двух независимых признаков:

| Категория | Короткая подпись |
| --- | --- |
| Важная и срочная | Сделать в первую очередь |
| Важная и несрочная | Запланировать время |
| Неважная и срочная | Решить оперативно |
| Неважная и несрочная | Можно отложить |

Просрочка — вычисляемый признак, который дополняет статус. Например, задача может одновременно быть «В работе» и «Просрочена на 2 дня».

Плановая дата отвечает на вопрос «Когда работаем?», срок сдачи — «К какому дню нужен результат?». Задача считается просроченной после окончания дня срока, пока она не выполнена и не отменена. При отсутствии срока показывается только факт переноса, без придуманного дедлайна. Завершение позже срока отражается в истории как выполнение с опозданием.

Внутри дня сначала отображаются просроченные активные задачи, затем задачи со сроком сегодня, далее — остальные по приоритету и сроку. Выполненные и отменённые отделены. Можно включить группировку по статусу или четырём категориям важности и срочности.

## 6. Перенос задач

На компьютере задачу можно перетащить на другой день недели или дату месяца. Для переноса за пределы видимого периода доступна команда «Перенести» с выбором даты. На телефоне это основное действие; работа не зависит от точности перетаскивания пальцем.

Перенос изменяет дату работы. Срок сдачи сохраняется, пока пользователь не изменит его отдельно. Если выбранная дата выходит за срок, карточка сразу показывает это. Можно перенести задачу на другую неделю или месяц без её повторного создания.

Для длительной задачи ручной перенос начала сдвигает весь рабочий интервал на то же количество календарных дней. Срок сдачи остаётся независимым. Исходный интервал и история изменений сохраняются.

Автоматический перенос работает по следующим правилам:

1. Незавершённые задачи со статусами «В плане», «В работе» и «Ожидает ответа» переходят в следующий календарный день. Выходные также участвуют в переносе.
2. Статус, исполнитель, срок и идентификатор задачи сохраняются. Новая копия задачи не создаётся.
3. Для длительной задачи перенос применяется после окончания её рабочего интервала. Во время интервала задача уже видна в соответствующих днях.
4. Выполненные, отменённые и запланированные только на будущие даты задачи не переносятся.
5. При пропуске нескольких дней задача появляется в текущем дне; история предыдущего плана остаётся доступной.
6. Каждая операция выполняется один раз независимо от количества открытых браузеров. Повторная проверка не создаёт дубликатов и не переносит задачу дальше сегодняшнего дня.

Предлагаемый общий часовой пояс команды — Europe/Moscow. Облачная ежедневная операция выполняет перенос при смене дня, даже когда страница закрыта. При открытии страницы дополнительно проверяются пропущенные операции. Одни и те же правила применяются при переходе между неделями, месяцами и годами.

## 7. Длительные и регулярные задачи

**Длительная задача** имеет начало и конец периода работы. Например, «Подготовить бюджет» со 2 по 6 ноября. Она видна во все дни интервала с общей меткой периода. В итогах недели или месяца это одна задача. После окончания интервала незавершённая задача остаётся в текущем дне; исходные даты и срок не теряются.

**Регулярная задача** создаётся по правилу: ежедневно, по рабочим дням, еженедельно в выбранные дни или ежемесячно в выбранное число. Можно задать дату завершения повторений. Для числа, отсутствующего в месяце, используется последний день этого месяца.

Каждое повторение — самостоятельная задача со своим статусом, сроком и историей. Выполнение отчёта за одну неделю не завершает отчёт за следующую. Незавершённое повторение переносится как обычная задача; будущие повторения продолжают появляться по расписанию.

При изменении регулярной задачи предлагается выбрать «Только эту» или «Эту и будущие». Выполненные и прошлые экземпляры не переписываются. Один экземпляр однозначно определяется серией и исходной датой повторения, что исключает двойное создание при одновременной работе сотрудников.

## 8. Прогресс и итоги

На главном экране всегда доступны три показателя: день, неделя и месяц. Фильтр сотрудника применяется к задачам и всем показателям одновременно.

Для каждого периода различаются выполнение его плана и фактический объём завершённой работы:

- **План периода:** уникальные задачи, запланированные хотя бы на один день периода, включая перенесённые из прошлого и добавленные по ходу работы.
- **Выполнение плана:** число задач этого плана, выполненных к моменту расчёта, делённое на число задач плана, умноженное на 100%.
- **Фактически завершено за период:** число задач с фактической датой завершения внутри периода, независимо от их первоначального плана.

Для текущего периода момент расчёта — сейчас, для прошедшего — конец его последнего дня. План на будущее показывает, сколько уже запланированных задач выполнено заранее. Если задач нет, отображается «Нет запланированных задач» вместо искусственных 0% или 100%.

При расчётах действуют следующие правила:

- Длительная или многократно перенесённая задача считается один раз внутри выбранной недели или месяца.
- Регулярные экземпляры считаются отдельно, поскольку это самостоятельные результаты работы.
- Перенос в следующий период не стирает задачу из истории предыдущего плана.
- Завершение в новом месяце не повышает задним числом процент выполнения прошлого месяца.
- Отменённые задачи показываются отдельно и исключаются из знаменателя с момента отмены. Поздняя отмена не меняет уже завершившиеся периоды.
- Удаление карточки сохраняет её прошлую историю и не улучшает задним числом результат.
- Общий процент рассчитывается по задачам команды, а не как среднее процентов сотрудников.
- История исполнителя сохраняется. Переназначение не удваивает задачу в командном итоге и не переписывает прошедшие результаты.

Экран «Итоги» содержит выбор месяца, фильтр сотрудника и следующие показатели:

| Показатель | Что помогает увидеть |
| --- | --- |
| Запланировано | Размер плана выбранного месяца |
| Добавлено в течение месяца | Появившиеся по ходу работы задачи, отдельно от начального плана |
| Выполнено из плана, % | Доля завершённых задач месячного плана |
| Фактически завершено | Все результаты, полученные в этом месяце |
| Осталось, в работе, ожидает ответа | Состав незавершённой работы |
| Просрочено | Незавершённые задачи с истёкшим сроком на дату расчёта |
| Выполнено с опозданием | Задачи, завершённые в месяце позже своего срока |
| Перенесено и отменено | Изменения плана за период |

Ниже располагаются небольшая диаграмма по неделям и таблица сотрудников: план, выполнение, процент и просрочка. Отдельно можно раскрыть список задач, из которого получился любой показатель. Формулы и состав выборки видны по короткой подсказке.

## 9. Работа команды и доступ

У каждого сотрудника своя учётная запись. Предлагаемый вход — электронная почта и пароль с сохранением сессии. Подключение к доске предоставляется конкретным сотрудникам; сама ссылка не открывает рабочие данные посторонним.

Предлагаемое распределение прав:

| Действие | Сотрудник | Руководитель |
| --- | --- | --- |
| Просмотр общей доски и итогов | Да | Да |
| Фильтрация по любому сотруднику | Да | Да |
| Создание задачи себе | Да | Да |
| Назначение другому сотруднику | Нет | Да |
| Изменение и завершение своих задач | Да | Да |
| Изменение и переназначение чужих задач | Нет | Да |
| Управление составом команды | Нет | Да |

Это предлагаемая модель прав для первой версии. Список сотрудников и первый руководитель задаются при настройке проекта. Добавление учётных записей можно выполнять через облачную административную панель, без отдельного сложного раздела в планировщике.

Изменения видны коллегам автоматически. При одновременном редактировании одной задачи используется проверка версии: более ранняя форма не должна молча затереть свежее изменение. Пользователь получает обновлённую карточку и понятное сообщение о конфликте.

## 10. Телефон и удобство работы

На телефоне области располагаются последовательно: краткий прогресс, выбранный день, полоса семи дат, задачи недели и сворачиваемый месяц. Полная недельная сетка заменяется списком дней, чтобы названия задач оставались читаемыми.

Кнопка добавления остаётся легко доступной. Редактирование открывается в удобной панели с крупными полями. Завершить, сменить статус или перенести задачу можно без перетаскивания.

На компьютере предусмотрены работа с клавиатуры, заметный фокус и сохранение по Enter. Для обеих версий нужны понятные состояния загрузки, пустого списка, ошибки сохранения и потери связи. Задача считается сохранённой после подтверждения облака; при ошибке введённый текст остаётся в форме.

Для просмотра и изменения общей доски в первой версии требуется интернет. При обрыве связи уже загруженный экран помечается как неактуальный; несинхронизированные изменения не выдаются за сохранённые. Офлайн-редактирование с последующим объединением изменений в первую версию не входит.

## 11. Техническая схема

Предлагаемая архитектура: **GitHub Pages + Supabase + три файла интерфейса**.

| Часть | Назначение |
| --- | --- |
| GitHub | Хранение исходных файлов и истории изменений страницы |
| GitHub Pages | Размещение статической страницы из HTML, CSS и JS |
| Supabase Database | Общие задачи, сотрудники, повторы и история плана |
| Supabase Auth | Вход и учётные записи сотрудников |
| Supabase Realtime | Получение изменений общей доски |
| Supabase Cron | Ежедневные облачные операции переноса и повторений |
| localStorage | Выбранные фильтры, вид экрана и другие настройки браузера |

GitHub Pages публикует статические файлы сайта. Это соответствует формату страницы из трёх файлов. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

Supabase предоставляет базу Postgres, API, авторизацию и передачу изменений. Использование этого управляемого сервиса позволяет обойтись без собственного обслуживаемого сервера. Это предложение архитектуры, а не уже подключённый сервис. [Архитектура Supabase](https://supabase.com/docs/guides/getting-started/architecture), [синхронизация изменений](https://supabase.com/docs/guides/realtime/postgres-changes), [вход по паролю](https://supabase.com/docs/guides/auth/passwords).

Облачные задания могут запускать функции базы по расписанию. Для планировщика это механизм переноса и создания повторений независимо от открытой страницы. [Supabase Cron](https://supabase.com/docs/guides/cron).

localStorage сохраняется между сеансами браузера и привязан к источнику страницы. В этой архитектуре он не является источником общих задач; очистка локальных настроек не удаляет рабочие данные команды. [Документация localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

Страница реализуется на HTML, CSS и JavaScript без обязательного фреймворка и сборки. Настройка таблиц, прав и облачных операций выполняется отдельно в Supabase. Таким образом, три файла относятся к интерфейсу; для общей доски также нужна конфигурация облачного сервиса.

Рекомендуемые сущности данных: команда, участники и роли, задачи, правила повторений, записи плана по датам и журнал изменений. Для задачи сохраняются автор, исполнитель, статус, приоритет, даты работы, срок, фактическое завершение, версия записи и связь с регулярной серией, если она есть.

Записи плана и события сохраняют исходные даты, переносы, смену исполнителя, отмену и повторное открытие. Это основа исторических итогов; расчёты не опираются исключительно на сегодняшнее состояние карточек. Изменение задачи и связанной истории должно сохраняться согласованно.

Права проверяются в облаке, а не только скрытием кнопок в интерфейсе. Доступ ограничивается участниками команды; роль руководителя не назначается пользователем самому себе. В файлах страницы допускается только публичный ключ приложения при настроенных правилах доступа. Административные ключи и пароли не публикуются в GitHub. [Правила доступа Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security).

## 12. Границы первой версии

В первую версию входят все основные согласованные сценарии: общая доска, сотрудники и фильтры, день/неделя/месяц, быстрое создание, статусы и приоритеты, сроки, переносы, длительные и регулярные задачи, автоматический перенос, прогресс и месячные итоги, работа на компьютере и телефоне.

Не включаются импорт старых таблиц, ручной экспорт/импорт для синхронизации, учёт часов, сложные проекты и зависимости задач, отдельное управление встречами, чат, вложения, рейтинги сотрудников и push-уведомления. Их добавление не требуется для описанного рабочего процесса.

## 13. Как проверить готовый планировщик

1. Руководитель и сотрудник входят в разных браузерах и видят одну доску. Созданная задача появляется у коллеги и на телефоне без передачи файлов.
2. Сотрудник создаёт задачу себе; руководитель назначает её другому сотруднику. Права соблюдаются и при обращении к данным, а не только на экране.
3. Добавление обычной задачи требует названия; дата и допустимый исполнитель уже подставлены. Фильтр сотрудника согласованно меняет список и прогресс.
4. Все семь дней видны в недельном обзоре. Переход к другой неделе и месяцу сохраняет ясную связь с выбранной датой.
5. Перетаскивание и команда переноса меняют дату работы. Срок сдачи остаётся прежним. На телефоне все действия доступны без перетаскивания.
6. Незавершённая задача автоматически появляется в следующем календарном дне, включая выходные. Проверяются также пропуск нескольких дней и граница месяца. История и просрочка сохраняются.
7. Длительная задача видна в своём интервале и считается один раз за период. Регулярные экземпляры имеют независимые статусы и не дублируются.
8. На небольшом наборе задач с известными результатами совпадают дневные, недельные, месячные и индивидуальные показатели. Перенос или позднее выполнение не переписывает прошлые итоги.
9. Одновременное редактирование не приводит к незаметной потере изменений. При потере связи нет ложного сообщения об успешном сохранении.
10. Неподключённый пользователь не получает задачи команды. Перезагрузка и очистка локальных настроек не удаляют облачные задачи.

## 14. Что требуется для реализации

После перехода к разработке понадобятся репозиторий GitHub, проект Supabase, список сотрудников и учётная запись первого руководителя. Эти действия в рамках подготовки концепции не выполнялись. Параметры доступа и подходящий тариф сервиса определяются при подключении с учётом размера команды и объёма данных; бесплатная эксплуатация без ограничений здесь не обещается.

Ключевое продуктовое решение согласовано: общая командная доска с облачным хранением. Название «Ритм», конкретный сервис Supabase, визуальные детали и правила реализации выше предложены как основа разработки.
